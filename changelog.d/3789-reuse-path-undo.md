### Fixed
- The already-active identity reuse arm of an auth-request approval now undoes its own writes when it loses the decision race: the grants and project membership it wrote through `add_agent_to_project` are rolled back with the same winner-sparing rules as the activation arm (grants a winning approval also holds, and its membership/lead on the same project, are left in place), instead of staying behind as usable authorization on a refused request. The reused identity itself stays active — the losing approval never activated it.
- A non-ValueError failure from `set_sponsorship` after activation (for example a store outage) now runs the approval undo instead of escaping with the identity left active: the activation is reverted and the original error surfaces. The error mapping is unchanged — a register() reserved-name ValueError still surfaces as itself, and only lifecycle-transition errors become the concurrent-decision 409.
- A cancellation of the approve task (`asyncio.CancelledError` — a `BaseException`, so the `except Exception` failure handlers never saw it) landing mid-writes on either approval arm now runs the same undo, shielded so the cleanup itself is not cancelled, instead of leaving a half-applied approval behind; the cancellation still propagates to the caller.
