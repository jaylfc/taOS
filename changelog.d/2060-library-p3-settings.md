### Added

- **Library P3 settings & storage cap (#2060)** — the Library settings pane is backed by a real API now instead of the #2276 localStorage mock. `GET/PUT /api/library/settings` persists `preferred_quality` (backend vocabulary: 360/480/720/1080/best) and `storage_cap_bytes` in the library database; the settings quality is the fallback default for heavy downloads after explicit, rule and item quality. `GET /api/library/usage` also reports per-source accounting (bytes by source), the largest items, the configured cap and whether downloads are paused at it. At the cap, heavy downloads pause instead of running: the trigger returns a surfaced `paused` state and the `heavy_download` job is recorded as `paused` with the reason — never a silent failure. Creating a duplicate source rule returns 409. The desktop pane wires quality, cap and rules to these endpoints, validates the cap (negative or non-integer values are rejected; 0 means no cap), blocks duplicate rules, and the "(mock until #2060)" label is gone.
