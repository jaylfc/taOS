### Added
- Device tokens now carry named scopes: `agents:read`, `decisions:answer`, `chat:send`, `agents:control`, `voice:stt`, `voice:tts`, `library:ingest`, `files:upload` and `push:register`. Every device-bearer route requires its scope; a missing scope is refused `403 device_scope_missing` naming the scope, and a path with no scope classified is refused the same way.
- Tokens issued before scopes existed (ios, watchos, android, stored with no scope list) resolve to an explicit legacy set (`push:register agents:read decisions:answer library:ingest files:upload chat:send`), so shipped taOSc builds keep working. A missing scope list is never read as "all" and never as "none" for those platforms; on any other platform it grants nothing. New pairings store their scope list explicitly.
- New device platforms: `embedded` (pairs only through the pairing Decision) and `wearos` (also accepted by `POST /api/devices/register`). Neither accepts a push token. Embedded defaults to `agents:read` and `decisions:answer`, and can never hold `library:ingest`, `files:upload` or `push:register`.
- Embedded tokens are accepted only on the TLS device listener (`TAOS_DEVICE_TLS_PORT`, default 6974); anywhere else they are refused `403 device_tls_required`. The check reads the connection's own scheme and port, never `X-Forwarded-*` headers. Until the listener lands, embedded tokens are unusable by design.
