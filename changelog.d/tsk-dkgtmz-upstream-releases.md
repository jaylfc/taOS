### Added
- Store Updates tab now detects upstream releases for docker-image apps: a daily, cached registry check (Docker Hub v2 `repositories/<ns>/<repo>/tags?ordering=last_updated`; GHCR via its token service + v2 `tags/list`) records the newest tag matching the pinned tag's shape per app (`latest` and other non-version tags are ignored).
- `/api/store/catalog` entries expose `upstream_version`, `upstream_update_available` and `upstream_checked_at` alongside `update_available`, which now also flips true when the cached upstream tag is newer than the catalog pin. Stale-pin apps (SearXNG: catalog 2024.12.0, upstream 2026.10.2) finally surface in the Updates tab, showing the version delta (`v2024.12.0 → v2026.10.2`).
- Upstream checks are cached with a 24h TTL (persisted to `data_dir/upstream_versions.json`), never run from a request handler, and never auto-upgrade. A network failure or uncheckable pin reads as unknown (`upstream_update_available: null`), not "no update".
