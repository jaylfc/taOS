### Fixed
- Single writer per archive directory: `app.py` is the only strict writer, opening the archive with component label ``controller.app``. All other sites (catalog routes, memory management, job worker) use the shared archive handle from ``app.state.archive`` or a read-only open, preventing multiple writer handles for ``<data>/archive``.
- `routes/catalog.py`: `_get_catalog`, `catalog_index`, and `catalog_rebuild` now use the shared archive from ``app.state.archive`` instead of constructing `SessionCatalog`/`CatalogPipeline` with ``data_dir / "archive"``.
- `routes/memory_management.py`: `_backend` now ensures the shared archive from ``app.state.archive`` is always passed to ``TaOSmdBackend``, falling back to the shared-handle helper if ``archive`` is not set on state.
- `scheduling/job_worker.py`: default paths (``"data/archive"``, ``"data/session-catalog.db"``, ``"data/crystals.db"``, ``"data/knowledge-graph.db"``, ``"data/sessions"``) resolved against the injected ``data_dir`` parameter instead of the process working directory. ``JobWorker`` now requires ``data_dir``; the relative-path defaults have been removed.
- Added `tinyagentos/archive_writer.py` stub providing ``open_archive_writer(label, archive_dir)`` (strict, one-writer-per-process, raises ``RuntimeError`` on second open naming the label) and ``open_archive_shared(archive_dir)`` (many readers allowed). When the real taosmd writer-lock change is released, only this helper needs to swap to the library's actual implementation.
