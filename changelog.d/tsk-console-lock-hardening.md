### Changed

- **Console lock hardening** -- PIN sign-in on the device screen now uses the same request gate as swipe unlock (custom header or JSON, same-origin, JSON body only) and the gate runs before the PIN throttle is touched. A locked console no longer carries a usable session: the controller drops the session cookie from console requests while the console is locked, ends the browser's session when the sign-in page is shown, and treats a screen-off signal as a lock. The shell's lock call now sends its CSRF header, checks the answer, and retries until the controller confirms.
- **Console identity needs a per-boot secret** -- a loopback address alone no longer counts as the device's own screen. The controller keeps a per-boot secret in a file readable only by the shell's user (`/run/taos/console-secret`, or `TAOS_CONSOLE_SECRET_FILE`; a group can be set with `TAOS_CONSOLE_SECRET_GROUP`). Scripts send it as `X-taOS-Console: <secret>`; the kiosk browser starts from `taos-console-url`, which trades the secret for a one-time start-URL ticket and an HttpOnly cookie. Kiosk start scripts must use `taos-console-url`; scripts that send `X-taOS-Console: 1` must send the secret instead.
- **PIN throttle persists** -- failed PIN counts are stored with the account state and survive a controller restart; the delay doubles per failure (30 s from the fifth, capped at one hour).
- **Lock screen** -- with swipe unlock, "Stop all agents" asks for the account password (the server requires it too), and the lock screen no longer says an action it does not carry across sign-in will be done.
